# 实验总览

本文件只解释“项目怎样走到当前方案”。当前协议、指标和下一步以 [论文主线 README](04_保留专门化/05_论文主线/README.md) 为准，具体结果以 [结果索引](04_保留专门化/05_论文主线/results/README.md) 为准。

## 1. 当前要解决的问题

目标是在没有全局通信和其他机器人真值的条件下，让五车导航同时具备：

- 普通状态下的目标推进与静态避障能力；
- 紧迫机器人交互下的减速、让行和避碰能力；
- 能够部署的状态级切换，而不是依赖场景名称或仿真真值。

当前方法不是 standard/dense 各放一个完整 Actor。空间密度和交互强度并不等价，而且同一条轨迹会在普通状态和紧迫交互状态之间变化。

当前系统定义为：

```text
frozen generalist-5a
  + frozen strong-interaction-5a-balanced epoch 16
  + deployable interaction-gate（待训练）
```

## 3. 研究演进

### 3.1 基础探索与课程学习

`01_第一次尝试` 完成了系统搭建和基础机制验证。`02_课程学习` 随后形成两个重要历史模型：

- `5A`：普通五车共享策略；
- `5D`：使用几何邻域 Critic 的历史 generalist 基线。

这部分证明普通多车导航可以训练，但没有解决紧迫交互。

### 3.2 直接 dense 训练为什么停止

早期 pure dense、PAIR/THREE 课程、完整 Actor fine-tune 和 standard expert 训练反复出现：

- warm-start 本身可以运行；
- Actor 解冻后已有能力退化；
- dense 成绩也没有形成稳定新增能力；
- 5A + 5D 的简单切换没有显示足够互补性。

因此不再把同一个 Actor 持续覆盖成“全能策略”，也不把 5D 直接称为 dense expert。

### 3.3 场景定义为什么改成固定随机池

过去的手工 tight case 和每次重新随机都会混入两类问题：场景可能无效，且不同运行并非面对同一批任务。现在采用：

- `standard` 和 `dense` 两个固定随机空间池；
- 只按初始碰撞、复位、传感器和路径可行性筛除无效场景；
- train、validation、test 使用互斥 seed 并冻结 manifest；
- 用同步名义冲突图描述 interaction density，不按模型成败筛 test。

这使“空间更密”与“机器人交互更强”可以分别统计。数据说明 dense 的 0-edge 场景仍然很容易，主要困难来自路径冲突，而不是地图缩小本身。

### 3.4 条件交互 Actor 如何得到

强交互 Actor 的有效配置保持原 TD3 Actor 结构，并采用：

- 从 5A Actor 初始化，Critic 重新训练；
- 冻结 5A 负责普通状态；
- 训练期仅在邻车真值距离 `<= 2.0 m` 时调用条件 Actor；
- Actor 只从安全聚焦交互样本更新；
- Critic 使用本车坐标系下的邻车相对位置和相对速度；
- 保留 `0.8 self + 0.2 neighbor` reward；
- deep/close/margin 均衡循环采样完整 2560 场训练池。

正式训练完成 16 epoch。匹配重复 validation 中，5A 单独运行与“5A + 条件交互 Actor”的 full success 为 `0.421/0.700`。这证明条件 Actor 在训练契约内有效，但不证明它能全程独立导航。

### 3.5 为什么普通 Actor 最终选择 5A

在相同 248 个固定 0-edge validation 场景上，5A/5D 的 full success 为 `0.875/0.871`，没有显著差异。选择 5A 的原因是：

- 它已具备足够的普通导航能力；
- 正式交互 Actor 就是在 5A 外围控制形成的轨迹分布上训练和验证；
- 避免再加入 5D 到 5A 的第三层切换。

5D 继续作为重要历史基线，但不属于当前待部署的双 Actor 组合。

## 5. 接下来只做什么

顺序已经固定：

1. G0：只用本机三维激光和本机 odometry 区分机器人与静态障碍。
2. G1：对识别出的机器人估计距离、方位、闭合速度、CPA 和 TTC。
3. G2：冻结两个 Actor，先验证可部署的启发式 Gate。
4. G3：G2 证明链路可行后，只训练 learned Gate。
5. 方法与阈值冻结后，才读取正式 test，并做多 seed、密度分层和消融。

当前禁止继续训练两个 Actor，也禁止用场景名称、冲突边、其他机器人位姿或 Critic 特权信息作为 Gate 部署输入。
