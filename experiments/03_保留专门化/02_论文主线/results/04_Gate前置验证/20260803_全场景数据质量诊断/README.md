# 全场景数据质量诊断

日期：2026-08-03

状态：`complete`。本诊断只读取固定manifest和策略无关的几何指标，不运行Actor、
不调整reward，也不依据历史成功率删除场景。

## 目的

在继续判断TD3、奖励或Gate之前，先检查自行生成的standard/dense
train/validation/test是否存在：

1. 初始非法、无静态路径或split泄漏；
2. train/validation/test难度分布漂移；
3. 规划净空与真实车体几何不一致；
4. 名义冲突是否实际要求机器人协调；
5. 固定路径能否仅通过错峰出发保持物理不接触。

## 静态审计初步结果

- 六个split共`13500`场，scenario ID和完整layout均无重复；
- 全部通过已有Gazebo reset和单机器人静态路径检查；
- 同一preset内validation/test相对train的最大标准化均值差小于`0.075`，冲突边分布
  total variation小于`0.037`，没有明显split难度漂移；
- 生成器的静态规划净空为`0.240 m`，低于根据实际Gazebo collision mesh和xacro
  偏置计算的Pioneer平面外接半径约`0.267 m`；
- 以外接直径`0.534 m`作为保守物理不接触下界，dense train/validation/test的名义
  同步路径进入该距离的场景分别为`4007/6000`、`659/1000`、`1355/2000`；
- 固定路径错峰检查使用更严格的`0.600 m`中心间距，相当于再加入约`0.066 m`总
  安全余量。

最后一项不是场景非法，而是说明dense数据大多数都不是独立导航问题，而是强制包含
动态协调。下节使用固定路径错峰检查估计其中有多少只需学习通行顺序即可解决。

## 固定路径错峰结果

每台车使用manifest同规则生成的静态路径和`0.5 m/s`速度，只搜索`0-8 s`、步长
`0.5 s`的出发延迟。要求全程中心间距至少`0.60 m`。该检查成功能证明存在简单协调
解；失败不证明场景不可解，因为它不允许途中停车、改道或改变速度。

| Pool | Train | Validation | Test |
| --- | ---: | ---: | ---: |
| standard | `2671/3000 = 0.890` | `452/500 = 0.904` | `889/1000 = 0.889` |
| dense | `4626/6000 = 0.771` | `786/1000 = 0.786` | `1534/2000 = 0.767` |

train/validation/test比例稳定。大部分dense场景只需安排通行顺序就能解决，不能把TD3
低成功率主要归因于场景不可解；但约`21%-23%`的dense场景超出本检查能力，应作为
更高难度层，不与简单单冲突场景混在初始训练阶段。

## 冲突标签问题

生成器只在前`8 s`计算名义冲突。dense任务短，六个dense split没有发现漏边；
standard路径较长，完整路径复算发现：

| Split | 总场景 | 漏边 | 原0/1边变为多边 |
| --- | ---: | ---: | ---: |
| train | 3000 | 23 | 11 |
| validation | 500 | 2 | 2 |
| test | 1000 | 9 | 3 |

当前edge-1派生视图中，train有`1/512`、validation有`2/423`实际为edge-2。比例很小，
不足以解释整体训练失败，但正式“单冲突到多冲突”实验必须按完整路径重算标签并排除
这3场，否则“训练只见单冲突”不严格成立。

epoch-16使用的2560场`full_train`中有`11`场实际为edge-2，占`0.43%`；其140场
validation没有漏边。因此现有Oracle多冲突结果仍是很强的先验，但不能严格宣称为
完全零样本多冲突。正式论文版本必须在修正后的纯单冲突集重新训练局部Actor，或把
现有结果明确标为近似无泄漏pilot。

## 几何模型问题

Pioneer实际Gazebo collision mesh按xacro偏置计算的平面外接半径约`0.267 m`，生成器
规划净空为`0.240 m`。使用`0.267 m`外接圆重规划会拒绝大量场景，但外接圆同时要求
任意朝向和原地旋转均安全，对有朝向的差速矩形车体过于保守；所有正式场景又已经
通过真实Gazebo reset。因此该结果说明生成器几何近似不严谨，不能据此判定或删除
场景。正式下一版应使用有朝向的差速车footprint做规划与可解性检查。

## 与策略证据合并后的判断

### 场景责任

- split没有泄漏，train/validation/test难度一致；
- 大多数dense场景有简单错峰解，不是天然不可解；
- 约两成是明显更高难场景，应该分层；
- 几何净空和standard的8秒冲突标签需要修正；
- 不允许按当前模型成功率手工删除失败case。

### 输入责任

原Actor 24维输入仅包含20个前向激光扇区最小值、目标距离/角度和上一动作。它不包含
机器人身份、相对速度或通行优先级。历史诊断中原始点云覆盖危险机器人的比例达到
`97.92%`，但20-bin单帧/时序风险编码均失败；加入目标级检测、跟踪、闭合速度和TTC
后，Gate validation达到`recall=0.861/FPR=0.111`。R0 Residual的交互teacher-choice
accuracy仅`0.487`。因此24维输入足以普通导航和部分反射式避障，但不足以稳定表达
“对方是谁、是否正在靠近、当前谁该让”。

### 训练责任

过去奖励和约束调整反复在碰撞与保守timeout之间切换；Critic还要在不可观测的其他
机器人动作下估计同一ego动作的后果。奖励系数会改变保守程度，但不能补回缺失状态。
所以独立强Actor失败不是必然，也不是只差一组reward系数，而是当前观测下TD3的
部分可观测性和多主体信用分配不稳定。

## 诊断结论

1. 场景并非整体不可用，但必须修正完整路径冲突标签并按可解性/拓扑分层。
2. 不再用完整dense混合池直接训练强Actor，也不再继续扫避让奖励。
3. 已有Oracle组合在未见`edge>=2`上把full success从`0.221`提高到`0.470`，说明局部
   单冲突技能可被重复调用；可部署Gate在独立exact-edge-2上从`0.325`提高到`0.405`，
   方向为正但未通过统计和Oracle收益恢复门槛。
4. 下一步应保留两个Actor，优先改进Gate的可观测交互表示；若仍坚持独立强Actor，
   最小必要改动是给Actor增加目标级相对运动/TTC特征，而不是继续改奖励。
