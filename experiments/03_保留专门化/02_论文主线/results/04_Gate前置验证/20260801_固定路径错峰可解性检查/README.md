# 固定路径错峰可解性检查

日期：2026-08-01

## 目的

判断Dense失败主要来自场景不可解，还是来自多车没有学会“谁先走”。本检查不运行Actor，也不调整reward：每台车沿manifest中相同规则生成的静态路径以`0.5 m/s`前进，只搜索不同的出发延迟，检查能否始终保持给定中心间距。

固定数据为`dense_validation_monitor_v1`的200场。延迟步长`0.5 s`，最大延迟`8 s`，轨迹采样周期`0.1 s`，静态规划净空`0.24 m`。

## 结果

| 最小中心间距 | 可由出发错峰解决 | 比例 | 平均所需最大延迟 |
| ---: | ---: | ---: | ---: |
| `0.6 m` | `161/200` | `0.805` | `1.258 s` |
| `0.7 m` | `124/200` | `0.620` | `1.282 s` |
| `0.8 m` | `79/200` | `0.395` | `1.228 s` |

Pioneer车体平面包围半径约为`0.30 m`，所以`0.6 m`用于检查接近物理不接触的下界；`0.7 m`和`0.8 m`分别加入约`0.1 m`和`0.2 m`总安全余量。结果对安全余量敏感，因此它是几何诊断，不是可部署控制器的成功率上界。

`0.6 m`阈值下，冲突边越多，单纯错峰越难：

| 冲突边 | 场景数 | 可解数 |
| ---: | ---: | ---: |
| 0 | 7 | 7 |
| 1 | 45 | 43 |
| 2 | 61 | 52 |
| 3 | 54 | 38 |
| 4 | 18 | 12 |
| 5 | 11 | 6 |
| 6 | 1 | 1 |
| 7 | 3 | 2 |

## 与Actor结果对齐

使用同一200场的固定评测结果：

| 方法 | 161个错峰可解场景中的full success | 39个错峰不可解场景中的full success |
| --- | ---: | ---: |
| 5A | `63/161 = 0.391` | `4/39 = 0.103` |
| v6 epoch-11 | `86/161 = 0.534` | `3/39 = 0.077` |

这说明错峰检查确实区分出了难度，但也暴露出主要训练缺口：即使在只需安排先后顺序的161场中，5A仍失败98场，v6仍失败75场。

## ORCA排查边界

本轮也尝试了官方RVO2和公开NH-ORCA有效点换算：

- 直接把全向ORCA速度转成差速动作会产生左右反复原地转向；
- NH-ORCA有效点换算在弱交互与Dense控制组中均会停止；
- manifest静态路径净空为`0.24 m`，而按真实车体和有效点得到的NH-ORCA有效半径约`0.40 m`，两者的可行空间并不一致；
- 当前Actor角速度限制为`|w| <= 1`，公开Turtlebot实现使用的近乎无限角速度换算也不能直接复用。

因此这些ORCA运行不能用于宣称场景不可解，也不保留为正式基线。若论文需要ORCA对比，应采用完整的差速约束实现并重新校准地图净空。

## 结论和下一步

1. 不应删除整批Dense场景，也不应继续把主要问题归因于reward大小；至少`80.5%`的固定场景存在“只调整通行顺序”就能避免物理接触的解。
2. 当前Actor的核心失败是没有稳定学会通行顺序，而不是完全不会静态导航。
3. 剩余`39/200`在固定路径和`8 s`起步延迟内无解，不代表场景非法；它们需要途中等待、换路或更强协调，应作为后一阶段而不是第一阶段训练内容。
4. 下一轮训练前先验证Actor观测能否判断对方运动方向和闭合趋势。保持TD3和MLP不变，比较当前单帧20-bin与多帧高分辨率激光；只有观测检查通过，才在“错峰可解”子集上训练让行和重新启动。
