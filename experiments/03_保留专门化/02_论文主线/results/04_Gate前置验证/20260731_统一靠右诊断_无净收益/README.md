# 统一靠右诊断：无净收益

日期：2026-07-31

目的：检查五车强交互中加入统一靠右通行约定，能否直接解决双方不让行的问题。该控制器只使用仿真真值做因果诊断，不是最终可部署方法。

## 控制器

- 基础策略：冻结5A。
- 仅在机器人距离不超过`1.5 m`、前向夹角不超过`35 deg`、航向差至少`150 deg`、闭合速度至少`0.2 m/s`且TTC不超过`3.0 s`时触发。
- 触发后双方各自右转，线速度上限为`0.45 m/s`。
- 单次最多覆盖20步；达到上限后，同一对机器人分开前不得立即重新触发。
- 墙和箱子不会触发该规则。

## 最终配对结果

在同一Gazebo进程内，每个固定case连续运行一次5A基线和一次靠右规则。完成10对case后停止，因为结果已经没有净收益。

| 指标 | 5A基线 | 5A + 靠右规则 |
| --- | ---: | ---: |
| agent success | `33/50 = 0.660` | `33/50 = 0.660` |
| collision | `17/50 = 0.340` | `17/50 = 0.340` |
| full success | `3/10 = 0.300` | `3/10 = 0.300` |
| mean episode steps | `36.0` | `21.2` |
| mean rule action share | `0` | `0.089` |

规则只在4/10个case实际触发。这4个case相对基线的成功机器人变化为`-3、+1、+1、0`，合计`-1`；没有证明正收益。

未触发规则的case仍出现明显轨迹波动，例如同一case分别运行220步和26步，以及成功数`1/5`和`2/5`。因此平均步数差异不能归因于靠右规则，单次Gazebo rollout也不能作为精确配对因果证据。

## 评测修复

本次同时修复了以下评测问题：

- reset前后发布零速度，避免继承上一episode命令；
- 固定步进使用Gazebo仿真时间，不再把Unix墙钟与传感器时间戳比较；
- 等待五台车模型、激光和里程计接口全部就绪；
- 检查激光与里程计是否属于当前步进窗口；
- 丢失的Gazebo Transport步进消息允许有限重试；
- 探针使用全局文件锁，禁止并发Gazebo评测造成串扰；
- 新增同一case连续运行基线/规则的`paired_cycle`协议。

归档配对运行仍在每个episode回退仿真时钟，日志出现了`Negative joint state update time difference`，所以它只用于否定明显无收益的启发式，不能作为论文最终数值。归档后已改为Gazebo暂停启动，通过`gz world --multi-step`推进物理，并在episode之间使用`reset_world`保持时钟单调；没有启用与Velodyne插件不兼容的`--lockstep`。

固定步进降低了波动，但Gazebo传感器调度仍不能做到逐轨迹bitwise确定。正式论文统计必须使用多次重复和置信区间，不能用单次逐场差异挑结论。

## 结论

“检测到迎面冲突后直接覆盖Actor并统一靠右”不产生净收益，不能据此生成监督示范，也不应直接加入下一轮Dense Actor训练。

它说明协调约定需要与局部几何、第三车冲突和恢复行为共同学习，不能由一个固定右转
动作代替。该历史结论不再导向完整Dense Actor；当前冻结5A和epoch-16，直接开发
可部署Gate。
