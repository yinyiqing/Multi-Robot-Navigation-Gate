# 导师 Reward-aware Gate Idea 对齐记录

更新时间：2026-09-12

状态：研究定义整理；未授权新一轮闭环实验。

## 1. 老师原话对应的准确含义

对于每一个 Gate 样本，样本基础状态保持相同。该样本至少包含部署时可用的本机观测/历史，
以及训练期生成的两个监督量：

```text
y_t = 1[最近的其他机器人距离 <= 2 m]
r_N,t = navigation actor 在该状态执行一步得到的共同评价 reward
r_I,t = interaction actor 在同一状态执行一步得到的共同评价 reward
Delta r_t = r_I,t - r_N,t
```

其中，`y_t` 是训练期的特权交互标签，`Delta r_t` 是两个冻结策略在同一状态下的一步
反事实 reward 差。两个 Actor 不重新训练，`y_t` 和 `Delta r_t` 都不能作为部署时的真值输入。

老师提出的最后一句意味着：部署时 Gate 应根据**预测的交互需求**和**预测的策略相对收益**
共同决定是否切换，而不是只用其中一个信号。具体的组合函数、阈值、滞回和最短保持时间需要
在实验前固定并记录。

## 2. 与此前实现的关系

此前的 reward-aware 版本并非全部等价于老师的定义：

| 版本 | 实际做法 | 主要问题 |
| --- | --- | --- |
| G27/B3 | 增加 reward head，并把一步 `Delta r` 作为相位/门控修正 | 一步终止 reward 对闭环后续影响不足，直接改变相位会放大少量错误 |
| G28/B4 | 对 `Delta r` 截断、冻结 B2 主干，再做边界融合 | 仍然是“改写 B2 决策”，没有形成独立且清楚的双监督 Gate |
| B6 | 少量 reward 锚点训练单头 | 数据覆盖不足，Gate 概率塌缩 |
| B7 | 完整数据和 B2 初始化，同时更新共享 GRU | 两个目标冲突，Gate 概率接近常数 |
| B8 | 冻结 B2 主 Gate，只用 reward head 在边界硬 tie-break | 即使保留 B2 主决策，错误的边界改写仍会损害闭环 |

这些版本说明“直接把一步 reward 差加到旧 Gate 的 logit 上”不稳健，但不能证明导师 idea
本身不可行。它们也不能被写成已经完成的最终 reward-aware 方法。

## 3. 当前应采用的概念模型

下一版若继续实现，应先明确为一个独立的双头时序 Gate，而不是继续在 B2 上叠加补丁：

```text
本机时序观测 -> temporal encoder
             -> y-head: 预测交互需求 p_y
             -> reward-head: 预测策略优势 Delta r_hat

(p_y, Delta r_hat) -> 预先固定的联合决策规则 -> hysteresis/hold -> Actor N 或 Actor I
```

训练目标可以是多任务目标：

```text
L = L_BCE(y_t, p_y) + lambda_r * Huber(Delta r_t, Delta r_hat)
```

这里的 `y_t` 和 `Delta r_t` 都是训练监督，不是部署输入；`lambda_r`、reward 归一化方式和
联合决策规则必须在读取闭环结果前冻结。

## 4. 不应再犯的错误

1. 不把 `Delta r_t` 当成当前时刻真实可观测的部署输入。
2. 不用 reward head 在推理时直接覆盖一个已经训练好的 B2 phase。
3. 不根据 32/64 场结果反复调阈值，再挑选看起来更好的版本。
4. 不把离线 reward 回归误差或 Gate 分类准确率当成闭环任务收益证明。
5. 不把 B2 作为最终主线；B2 只可作为旧版内部对照、初始化来源或诊断参照。
6. 不把 G25 sealed 结果改写成 reward-aware 新方法结果。

## 5. 在启动实验前必须完成的检查

1. 审计每个样本的 `y_t`、`r_N,t`、`r_I,t`、`Delta r_t`，确认两个 Actor 确实从同一状态
   各执行一步，并记录 goal/collision/timeout 等 reward 分量。
2. 报告 `Delta r_t` 的分布、极端值、与 `y_t` 的冲突率，以及不同交互距离层的覆盖。
3. 明确部署时只能由本机观测预测 `p_y` 和 `Delta r_hat`。
4. 预先写下唯一的联合决策规则及停止条件；先做 32/64 场 pilot，只有方向和行为没有崩溃
   才能申请 256 场独立评测。

在上述检查完成前，G29 仍只是一个尚未验证的候选实现，不应直接作为论文主线或启动完整队列。

## 6. 是否需要补采集

需要。当前 G27-P1 只有 251 个训练 reward anchors 和 57 个验证 reward anchors，而对应的
Gate 训练/验证帧约为 70,981/4,785。也就是说，当前只有约 0.35%/1.19% 的 Gate 帧同时拥有
`y` 和 `Delta r`。这不足以支撑一个声称在整个 Gate 数据上联合学习的实验。

但不应机械地把全部历史帧逐一重跑。更合理的做法是先固定“哪些 Gate 样本进入联合监督集”，
并保证每个被选中的样本都具有同状态的 `y`、`r_N`、`r_I`、`Delta r` 和 reward 分量。首轮
数据质量采集应覆盖八个既有分层，目标至少为每个分层 64 个有效训练样本和 16 个有效验证
样本；由于旧流程约一半候选会因参考分支失效，实际候选数需按审计结果补足。首轮只验收：

- 两个 Actor 是否从同一状态各执行一步；
- 两个分支的 goal/collision/timeout 记账是否完整；
- 终止惩罚是否被单独记录，不能与普通一步推进 reward 混为一个不可解释的数；
- `Delta r` 的极端值比例、分层覆盖和 train/validation 场景互斥。

这批数据质量验收通过后，才训练独立双头 Gate 并做 32/64 场 pilot；pilot 未通过前不启动
256 场长跑。
